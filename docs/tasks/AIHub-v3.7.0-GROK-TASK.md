## 1. Что такое AIHub (контекст)

AIHub — self-hosted веб-приложение (Telegram WebApp) для управления агентами двух систем:

- **DeepSeek Harness (DSH)** — веб-интерфейс на `127.0.0.1:3080`, API сессий/сообщений;
- **OpenCode** — сервер `opencode serve` на `127.0.0.1:4096` (v1/v2 API), сессии/модели/действия.

Компоненты (v3.6.0):

- **gatekeeper** (FastAPI) — UI-шелл, авторизация, API агентов/сессий/метрик, прокси DSH, WebSocket;
- **агрегатор** — поллинг DSH и OpenCode, единый стейт агентов/чатов, действия, WS-события;
- **notifier** — уведомления владельцу в Telegram;
- **tunnel-watcher** — Tailscale Serve (mesh HTTPS), обновление `PUBLIC_URL` и кнопки меню в Telegram;
- **vault** — шифрованное хранилище секретов (ключ в macOS Keychain, в `.env` секретов нет);
- 4 службы launchd: `ai.aihub.gatekeeper`, `ai.aihub.opencode`, `ai.aihub.dsh-web`, `ai.aihub.tunnel-watcher`.

Сеть: `NETWORK_MODE=hybrid` — дома LAN (HTTP), вне дома Tailscale Serve (HTTPS, только внутри tailnet, без Funnel).

Стек: Python 3.14, FastAPI, httpx, pydantic; фронтенд — ванильные HTML/CSS/JS без сборки; тесты pytest.

Что уже сделано в v3.6.0 (не переделывать): мастер настройки (`setup.sh`/`setup_wizard.py`),
шифрованное хранилище, hybrid-сеть, кнопка меню в Telegram, smoke/acceptance-проверки, доки.

## 3. Задача A — новый интерфейс (полный редизайн `static/`)

Стиль — **Gemini-подобный Material**: крупные скругления, «пилюли», мягкие тени/градиенты,
аккуратные микроанимации; тема **авто** (как Telegram/система), день и ночь; mobile-first; safe-area.

- **A1. Сплэш:** анимация **сборки логотипа AIHub из частиц** (canvas/CSS), адаптивна к теме;
  показывается, пока грузятся данные; плавно растворяется в интерфейс; жёсткий потолок ~2,5 с (если данные ещё грузятся — дальше скелетоны).
- **A2. Шапка:** лого/название + сегмент-переключатель `Все · DSH · OpenCode` (всегда видим),
  мини-индикаторы статусов DSH/OpenCode.
- **A3. Нижняя навигация:** `Чаты · DSH · OpenCode · Ещё` (SVG-иконки, подписи, safe-area, высота 56–64px).
- **A4. Боковое меню** (свайп от левого края + кнопка, как в Gemini/GPT/Claude): «+ Новый чат»,
  поиск, «Закреплённые», «Архив», история с группировкой (Сегодня / Вчера / 7 дней / Раньше),
  внизу — «Ещё»/настройки. Оверлей, закрытие тапом/свайпом.
- **A5. Список чатов:** строка — название (≤2 строк), бейдж системы (DSH/OC), точка статуса, время,
  превью последнего сообщения; действия (долгое нажатие или «…»): закрепить/открепить,
  переименовать (диалог), в архив/из архива, удалить (подтверждение).
  Состояния списка: скелетоны загрузки, пусто (иллюстрация + текст), ошибка (retry), оффлайн-баннер.
- **A6. Экран чата:** шапка (название, модель/проект, статус), лента сообщений (user/assistant/system/tool;
  код-блоки; время; кнопка «копировать»), индикатор «работает/печатает», поле ввода (авто-рост до 5 строк), безопасный рендер (экранирование HTML, без сырого `innerHTML` с данными),
  кнопка «Отправить»/«Стоп» (меняется по статусу), действия агента
  (approve/deny/permission_always, answer_question, change_model, fork, revert) — контекстными плашками.
  Дополнительно: **поиск внутри чата** (подсветка, переходы) и **экспорт текста** (копировать / скачать .txt).
- **A7. Вкладка DSH:** встроенный настоящий DSH web внутри приложения (iframe через существующий прокси
  `{secret}/dsh/…`), кнопка «открыть отдельно», понятные состояния загрузки/ошибки/оффлайна.
- **A8. Вкладка OpenCode:** свой экран в стиле AIHub — список сессий OpenCode (поиск/сортировка) + чат как A6.
- **A9. Вкладка «Ещё»:** всё текущее: статусы DSH/OpenCode, метрики/circuit, порты, настройки,
  диагностика, kill switch, подтверждения дорогих действий, ссылки (LAN/mesh), «полный интерфейс DSH».
- **A10. Паритет:** любые функции текущего UI сохраняются; сверка — по v3.6.0 (`static/`).
- **A11. Поведение Telegram:** использовать `Telegram.WebApp` (theme, initData, BackButton, HapticFeedback
  по возможности); в браузере — всё работает без Telegram (локальный вход).
- **A12. Производительность/доступность:** 60 fps, transform/opacity, `prefers-reduced-motion`,
  тап-зоны ≥44px, контраст AA, без внешних шрифтов/иконок (SVG инлайн).

## 4. Задача B — чаты: действия, автонейминг, поиск, экспорт

Существующие действия (сохранить): `send`, `interrupt`/`abort`, `delete`, `rename` (OpenCode),
`approve`/`deny`/`permission_always`, `answer_question`, `change_model`, `fork`, `revert`, `new_session`.
DSH-маппинг в `src/common/dsh_client.py` (path_map): send/interrupt/abort/approve/deny/change_model/delete.

- **B1. Создание чата:** «+» → быстрый чат; система — по текущему фильтру; на «Все» — выбор DSH/OpenCode.
- **B2. Переименование DSH — реализовать.** Сейчас в path_map нет rename. Добавить кандидаты
  (`PATCH /api/sessions/{id}` с `{title}`, `POST /api/sessions/{id}/rename`) и пробовать по очереди;
  если ни один не работает — использовать **локальный оверрайд названия** (B4) и вернуть `ok:false`
  с пометкой «локально».
- **B3. Удаление:** обе системы + подтверждение (как в v3.6.0).
- **B4. Локальные метаданные (новое):** `data/pins.json`:
  `{"pinned": [ids], "archived": [ids], "titles": {"<agent_id>": "Имя"}}`.
  Применяются в агрегаторе при формировании AgentState (title override, флаги pinned/archived).
  API: добавить `GET/POST {secret}/api/chats/meta` (или расширить `/api/agents`).
- **B5. Автонейминг (новое):**
  - переименовывать **только технические** названия: `^evt_`, `^ses_[0-9a-f]{8,}$`, `^[0-9a-f]{12,}$`,
    «Сессия ДД.ММ», «Session …» без слов;
  - имя: **2–4 слова, русский, ≤40 символов**, по содержимому (первые ~5 сообщений, обрезанных,
    + модель/проект);
  - вызов — через OpenCode: **бесплатная модель** (`space-bunny-free`); если недоступна — любая
    бесплатная (`*-free`, например `mimo-v2.6-flash-free`, `nemotron-3.5-lightning-free`) из
    `GET /api/model`; если и её нет — fallback «первая строка первого сообщения» (≤40 символов);
  - служебная сессия для нейминга — скрытая (id в `data/names.json`), из списка чатов исключается;
  - кэш результатов в `data/names.json`; повторно не переименовывать; вручную названные — не трогать;
  - троттлинг (например, ≤10 чатов за проход, ≥6 c между запросами), backoff при ошибках;
  - **бэкфилл** существующих чатов — фоново, не блокируя UI, с логом прогресса.
- **B6. Поиск внутри чата:** клиентский фильтр по загруженной истории (+ серверный `/api/search` как бонус).
- **B7. Экспорт:** собрать историю в текст, «копировать» и «скачать `AIHub-<имя>-<дата>.txt`».

## 5. Задача C — вкладки DSH / OpenCode (техника)

- **C1. DSH в iframe:** same-origin через существующий прокси. Если upstream шлёт свой
  `X-Frame-Options`/CSP — перезаписывать в прокси так, чтобы встраивание в наше приложение работало

## 6. Задача D — автопилот сети (полная спецификация)

### D1. Автонастройка Tailscale Serve (новый модуль + сторож)
- Проверка каждые ~15 с: gatekeeper готов → `tailscale status` ок → состояние serve.
- Нет serve-конфига (или он наш — на порт `GATEKEEPER_PORT`) → настройка:
  `tailscale serve --bg --https=443 http://127.0.0.1:<PORT>` **с ограничением времени (~15 с)** —
  CLI умеет «висеть» (живой баг на macOS), процесс обязательно убивать по таймауту.
- Разбор вывода:
  - успех (есть `*.ts.net`) → записать `PUBLIC_URL` в `.env`, сбросить кэш настроек,
    поставить кнопку меню (D6), уведомить владельца один раз «внешний доступ готов»;
  - `Serve is not enabled` → извлечь ссылку `https://login.tailscale.com/f/serve?node=…` →
    уведомить владельца (не чаще 1 раза в 3 ч), повторять попытки каждые ~5 мин;
  - ошибка/упоминание HTTPS-сертификатов → ссылка `https://login.tailscale.com/admin/dns`, уведомление (3 ч);
  - `AcceptDNS` выключен (`tailscale dns status`) → если `TAILSCALE_AUTODNS=1` (по умолчанию) —
    выполнить `tailscale set --accept-dns=true` и уведомить; иначе — уведомление с командой;
  - прочие ошибки → уведомление (не чаще 1 раза в час).
- Чужой serve-конфиг (не наш порт) — **не трогать**, уведомить (6 ч).
- Выключатели: `TAILSCALE_AUTOSERVE=1|0` (default 1), `TAILSCALE_AUTODNS=1|0` (default 1).
- Скрипт `enable_tailscale_serve.sh` переиспользует эту логику и больше не виснет.

### D2. Определение канала клиента
- `classify_ip`: `loopback` / `lan` / `tailscale` (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`) / `other`.
- На авторизованных запросах владельца — `data/netstate.json` (атомарно):
  `{last_channel, last_seen_ts, last_lan_ts, last_ts_ts}`.
- `/health` (доверенным) отдаёт `last_channel`; `status.sh`/`open_url.sh` печатают «последний вход: …».

### D3. Диалог в боте (new: `src/tunnel/bot_dialog.py`, long-polling в стороже)
- Только владелец (`OWNER_TELEGRAM_ID`); остальные игнорируются молча.
- Команды: `/start`, `/link` — приветствие + статус (внешний доступ: ок/настраивается/выключен;
  телефон: на связи/нет; последний вход: дома/снаружи) + inline-кнопки:
  «Дома без VPN» (LAN, http) и «Вне дома» (https `*.ts.net`) — когда доступны.
- `setMyCommands`: start, link.
- Пропуск старого бэклога при запуске; offset в `data/tg_offset.json`; backoff 5→60 с при ошибках.
- Пауза для мастера: `data/.tg_poll_pause` — `setup_wizard.py` создаёт перед работой, ждёт ≤20 с,
  удаляет после; бот при наличии файла не читает обновления.

### D4. Напоминания «включите Tailscale»
- Условия (все): serve настроен и URL отвечает; `tailscale` ок; за 24 ч телефон не был онлайн в tailnet
  (пиры с `OS ∈ {iOS, Android}`; если их нет вовсе — считаем «не виден»); не было LAN-заходов
  (`last_lan_ts` старше 24 ч); с прошлого напоминания ≥24 ч. Флаг: `data/.ts_remind`.
- Выключатель: `TAILSCALE_REMIND=1|0` (default 1).
- Если Tailscale не установлен — отдельное напоминание с инструкцией (тот же троттл).

### D5. `scripts/go.sh`
- Идемпотентно: `start_all.sh` (если нужно) → дождаться health → показать статус → `open_url.sh`.

### D6. Кнопка меню в Telegram
- Ставить и как default (без `chat_id`), и явно в чат владельца (`chat_id`): Telegram иногда
  задерживает применение default. При ошибке — уведомление (не чаще 1 раза в час).
